# OpenFront references and third-party services: the launch audit

DeltaFront is a fork of OpenFront. This is the M7 inventory of what still points at OpenFront or at any outside service, sorted into **KEEP** (licence, attribution, history, upstream-merge compatibility) and **REMOVE / REPLACE** (a runtime dependency, an account API, analytics, ads, a community link or a private backend). Three tests keep it true:

- `tests/NoOpenFrontDependency.test.ts`: no OpenFront host in any source file, template or the account API, outside a comment;
- `tests/ThirdPartyHosts.test.ts`: every `https://host` in client, server and account-API code is on the audited list below; a new one fails the build until someone decides it belongs;
- `npm run launch:check`: scans the **built** client for OpenFront hosts and for every secret value.

## Conclusion

**The production account, store, clan and multiplayer flows need zero OpenFront services.** Evidence: sign-in, sessions, profiles, Credits, the store, clans, leaderboards, server discovery, game archive and join verification are all served by `src/account-api` on the operator's own `api.<domain>`; the client and game server derive that address from `DOMAIN` and contain no OpenFront host in code; the real-game-server end-to-end test (`tests/account-api/joins.e2e.db.test.ts`) fails if the API or the game server's log names one; the browser run in M7 recorded every request the page made and none went to an OpenFront host (see "Verification" in the M7 appendix of DeltaFrontAccountsPlan.md).

What is **not** finished is a licence duty, not a dependency: see "Launch blockers" below.

| What                                                                                         | Why                                                                                                |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `LICENSE`, `LICENSE-ASSETS`, `LICENSING.md`, `CREDITS.md`, `CONTRIBUTING.md`                 | AGPL-3.0 and asset licences; the "© OpenFront and Contributors" notice must stay visible (AGPL §7) |

| `@openfront/*` package names and import paths                                                | kept on purpose so upstream merges stay mechanical                                                 |
| Code comments and `docs/*` that describe upstream behaviour (hosts like `blue.openfront.io`) | documentation of how the code was designed; comments only, never executed                          |
| `nginx.conf` / `generate-nginx-upstream.sh` identifier `openfront_workers`                   | an internal upstream name inside the container                                                     |
| `NewsMarkdown.ts` patterns for `github.com/openfrontio/...` pull-request and compare URLs    | rewrites such URLs in a news item _if one is written_; creates no link by itself                   |
| Test fixtures that use `openfront.io` style hosts                                            | data for host-parsing tests (`ClientEnv`, `ServerList`, …), not requests                           |
| `.claude/skills/*`, `map-generator/` module path                                             | developer tooling, not part of any deployment                                                      |

### Launch blockers found by this audit

1. **AGPL-3.0 §13 source offer.** DeltaFront is a _modified_ network application; players must be offered the source of **this** version. `BRAND.sourceRepoUrl` (`src/client/Branding.ts`) still points at the upstream repository, which does not contain DeltaFront's changes. Publish the DeltaFront source (the repository that holds this code) and put its URL there. `npm run launch:check` fails the `branding` check until this is done.
2. **Terms of Service and Privacy Policy** are placeholders (a plan item; see Deployment.md §11). Detected and blocked by `launch:check` and by the production game server.

## Third-party scripts and hosts

The browser loads **no third-party script on a plain DeltaFront page except Cloudflare Turnstile**. Everything else is conditional, optional or a link.

| Host                                                                                          | What                                                        | When                                                                                                              | Data it sees                                                                                         | Controls                                                                                                                |
| --------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `challenges.cloudflare.com`                                                                   | Turnstile bot check (script, iframe, verify)                | when a player joins a game                                                                                        | IP, browser signals, the page hostname                                                               | required; CSP `script-src`, `frame-src`, `connect-src`                                                                  |
| `sdk.crazygames.com`                                                                          | CrazyGames SDK                                              | **only** when embedded on crazygames.com (inline loader in index.html)                                            | whatever CrazyGames collects there                                                                   | CSP `script-src`; loader checks the embedding page                                                                      |
| `cdn.discordapp.com`                                                                          | Discord avatars, clan pictures                              | when a profile or clan shows one                                                                                  | the player's IP (an image request)                                                                   | CSP `img-src`                                                                                                           |
| `discord.com`, `accounts.google.com`, `oauth2.googleapis.com`, `openidconnect.googleapis.com` | OAuth sign-in                                               | when a player signs in; contacted by the **account API** (token and profile) and by the browser (authorize page)  | account id, name, avatar, e-mail (scopes `identify email` / `openid email profile`)                  | provider app settings; the API logs no codes or tokens                                                                  |
| `api.resend.com`, `api.postmarkapp.com`                                                       | Sign-in e-mail delivery (M8)                                | **only** if `DF_EMAIL_AUTH` is on and `EMAIL_PROVIDER` names it; called by the **account API**, never the browser | the recipient address and the one-time link (the link is the credential until it is used or expires) | env; the browser never contacts them, so the CSP is unchanged                                                           |
| `discord.gg`                                                                                  | clan invite links                                           | only a link a clan leader entered (validated to `discord.gg/<code>` or `discord.com/invite/<code>`)               | none until clicked                                                                                   | validation in `domain/clans.ts`                                                                                         |
| `www.googletagmanager.com`, `www.google-analytics.com`                                        | Google Analytics 4                                          | **only** if `GOOGLE_ANALYTICS_ID` is set                                                                          | page views, IP                                                                                       | env; CSP allows these hosts only when it is set                                                                         |
| `static.cloudflareinsights.com`                                                               | Cloudflare Web Analytics                                    | **only** if `CLOUDFLARE_ANALYTICS_TOKEN` is set                                                                   | page views                                                                                           | env; same                                                                                                               |
| `www.youtube.com`, `www.twitch.tv`, `embed.twitch.tv`                                         | links to a stream channel; the Twitch player SDK            | only if the optional streams feed names a featured stream (it is empty)                                           | the player's IP once the player loads                                                                | `GET /streams.json` (empty); CSP does not allow the Twitch player, so enabling streams requires a deliberate CSP change |
| `github.com`                                                                                  | links: source repository, contributor profiles in news text | when clicked                                                                                                      | none until clicked                                                                                   | `BRAND.sourceRepoUrl`                                                                                                   |
| `store.steampowered.com`                                                                      | Steam wishlist link                                         | hidden unless `BRAND.steamAppId` is set (it is `null`)                                                            | none                                                                                                 | `BRAND`                                                                                                                 |
| `clanmap.localhost`                                                                           | clan-map iframe address in development                      | the clan map is disabled (no map service exists)                                                                  | none                                                                                                 | `clanMapEnabled()`                                                                                                      |

The account API itself calls out to exactly four kinds of host: the OAuth providers above, Cloudflare's `siteverify` endpoint, the chosen e-mail provider when email sign-in is on, and nothing else (a test records every outbound request in the OAuth flow).

## Removing more later

Safe future clean-ups, none needed for launch: delete the inert upstream workflows and `deploy.sh`/`update.sh`/`setup.sh`; rename `openfront_workers`; replace the `@openfront/*` scope (breaks upstream merges, so only when DeltaFront stops merging upstream).
